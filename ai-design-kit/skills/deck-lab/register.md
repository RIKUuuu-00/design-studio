# テンプレ登録

社内テンプレを取り込み、deck-lab が使えるカタログ（`layouts.md` / `layouts.json` / `thumbs/`）にする。
テンプレを差し替えたときも同じ手順で再登録する（layouts.md に書いた「用途」はレイアウト名で引き継がれる）。

## 手順

1. テンプレを `design-system/slides/template.pptx` に置く（`.potx` でもよい。`.ppt` は PowerPoint か LibreOffice で `.pptx` に変換してから）
2. 環境を確認する

   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doctor.py --template design-system/slides/template.pptx --image-test design-system/slides/.image-test.png
   ```

   続けて `.image-test.png` を Read で開き、書かれた合言葉が出力どおりに読めるか確かめる（読めたら画像は消してよい）。読めなければゲートウェイが画像入力を通していないので、自己検証は check_deck.py だけで行うことになると利用者に伝える。

   テーマフォントが NG なら、利用者にフォント導入を依頼する。導入できない場合は、文字量判定に 1 割の余裕を残す運用（`check_deck.py --margin 0.1`、既定値）で吸収すると伝える。

3. 登録する

   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/register_template.py design-system/slides/template.pptx
   ```

   LibreOffice が無い環境では `--no-render` を付ける（サムネ無しでカタログだけ作る）。

4. `design-system/slides/thumbs/sheet.png` と各 `thumbs/Lxx.png` を見て、`layouts.md` の各レイアウトの **用途** を 1 行で埋める
   - 書き方: どんな主張・内容に使うか。例「1 つの主張を箇条書き 3〜5 点で支える」「2 案の比較」「章の区切り」「表紙」
   - 使うべきでないレイアウト（装飾用・旧版の残骸など）は「使わない（理由）」と書く
5. 構造チェックの結果を利用者に返す。テンプレ側を直すのが最も効くので、直し方を具体的に添える:

| 指摘 | 直し方（PowerPoint のスライドマスター表示で行う） |
| --- | --- |
| レイアウト名が既定名のまま | 用途が分かる名前に変える（例「本文_箇条書き」「比較_2列」） |
| タイトルのプレースホルダーが無い | レイアウトにタイトル枠を追加する |
| 本文がテキストボックスで組まれている | テキストボックスをプレースホルダー（コンテンツ / テキスト）に置き換える |
| 見本文らしき固定テキスト | レイアウトから削除し、必要ならプレースホルダーのプロンプト文にする |
| 同名レイアウトが複数 | 名前を変えて区別する |
| プレースホルダー同士の重なり | 位置を調整する |
| テーマフォントが環境に無い | 検証環境にフォントを入れる |

6. 返答: レイアウト数、用途を埋めた結果の一覧、構造チェックの要約（直すと効く順）

## 注意

- テンプレ自体は書き換えない。直すのは人（テンプレ管理者）
- テンプレ内のサンプルスライドは流し込みでは使わない（build_deck は既定で外す）。図解の見本として参照するだけ
