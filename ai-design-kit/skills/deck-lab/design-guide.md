# 資料デザインの指針

deck-lab で「見た目の完成度」を上げるための判断基準。
考え方の土台は frontend-design（`${CLAUDE_PLUGIN_ROOT}/references/frontend-design/frontend-design.md`。公式プラグインが有効ならそちら）で、
それを **スライド・日本語・テンプレ準拠** に読み替えたもの。デザインモードでは最初に frontend-design 本体も読む。

## 1. まず中身から決める

- 資料の **主題・読み手・資料の仕事**（何を決めてもらうか）を 1 行ずつ書く。見た目の判断はすべてここから導く
- 例: 「営業日報の改善 / 営業本部長 / 試行の承認をもらう」→ 数字で現状を突き付け、打ち手は段階で見せ、最後に判断事項を 1 枚で
- 文章も設計の一部。**主張タイトルは 1 文で結論**、要点は短い動詞止めか体言止めに統一、専門用語は読み手の言葉に直す

## 2. デザイン方針を立てる（デザインモード、またはテンプレ内での構図選び）

frontend-design の「計画 → 計画の見直し → 作る → 自己批評」をスライドで行う。

### 計画（`decks/<slug>/design-plan.md` に書く）

| 項目 | 書くこと |
| --- | --- |
| 色 | 4〜6 色に名前を付ける（例: 濃紺 #123A5A＝基調、青 #1D63B8＝強調、灰＝補足）。テーマの dk1/lt1/dk2/lt2/accent1〜6 への割り当て |
| 文字 | 見出しと本文の書体（1〜2 種類）。導入済みのフォントから選ぶ（doctor.py の一覧） |
| 構図 | 表紙・章扉・本文の型（theme.json の cover / section / title_rule）と、本文で使うパターンの方針 |
| 見せ場 | **大胆にする場所を 1 か所だけ** 決める（表紙、核心の数字、判断事項のどれか）。他は静かに保つ |

### 見直し

計画を書いたら、**同じような依頼なら毎回これになるのでは？** と自問する。なるなら、その部分を主題に寄せて直し、何をなぜ変えたかを design-plan.md に 1 行残す。
ただしブリーフや社内テンプレの指定は常に優先する（「無難に」と言われたら無難にする）。

### 資料でよく出る「生成っぽさ」（避ける。指定があれば従う）

- どのスライドも同じ角丸カードの 3 列並び、薄い影、グラデーションの飾り
- 意味のない番号（01 / 02 / 03）。番号は手順・順序があるときだけ
- 見出しの 1 語だけ色や太字を変える強調、英字の大文字ラベルを見出しの上に毎回置く
- 左端の色帯・アクセントストライプを全スライドに置く
- アイコンを飾りとして全要素に付ける
- 「・」で区切ったメタ情報の羅列、意味のない「→」

## 3. パターンの選び方

本文スライドは「タイトルのみ」レイアウト＋パターンで組むと、余白・文字サイズ・色が自動でそろう。

| 伝えたいこと | パターン | 注意 |
| --- | --- | --- |
| 核心の数字を突き付ける | `kpi` | 2〜3 個。強調したい 1 つを `highlight`。下に `caption` で「だから何か」 |
| データの傾向と示唆 | `chart_takeaway` | グラフの `highlight` でタイトルの主張と同じ要素だけ色を付ける |
| 選択肢を比べて推奨する | `compare` | 推奨案を `highlight`。最後に `verdict` で一言評価 |
| 手順・段階 | `steps` | 3〜5 段。今どこかを `current` |
| 日程・経緯 | `timeline` | 4〜6 点。現在地を `current` |
| 優先順位・位置付け | `matrix` | 軸ラベルは「低 → 高」まで書く |
| 並列の要素（効果・特徴） | `cards` | 3〜4 個。手順でなければ番号を付けない |
| 判断事項・結論 | `statement` | 1 文。補足は `sub` に 1〜2 文 |
| 目次・現在地 | `agenda` | 章扉の前に置くなら `current` |
| 数値の一覧 | `table`（add） | 強調行を `highlight_rows`。数値列は右寄せ |

- 同じパターンを 3 枚以上続けない（単調になる）。続くなら別の見せ方を検討する
- 1 枚に詰め込まない。要点が 5 個を超えたら分ける

## 4. 日本語の組版

- **表示用の大きな文字（表紙・章扉・statement・kpi の数値）は、文節の切れ目で `\n` を入れて改行位置を決める**。自動改行に任せると「デジ / タル」のように語の途中で切れる
- 段落の最終行が 1〜2 文字だけにならないようにする（check_deck の `widow`）。言い回しを変えるか改行を入れる
- 数字・英字は半角。単位の前に空白を入れない（「25分」「62%」）
- 1 行は全角 40 文字程度まで。それ以上は列を分けるか、文を短くする
- 箇条書きの文末を 1 枚の中でそろえる

## 5. 自己批評（作ったあと）

frontend-design の「鏡を見て、アクセサリーを 1 つ外す」。

- 画像化したサムネ一覧を見て、**どのスライドが一番目に残るか** を言えるか。言えなければ見せ場が弱い
- 装飾（線・面・色）を 1 つ外しても伝わるなら外す
- 隣り合うスライドでタイトル位置・余白・文字サイズがそろっているか
- 最後に `checklists/deck-critique.md` で採点する（design-reviewer の critique モード）
