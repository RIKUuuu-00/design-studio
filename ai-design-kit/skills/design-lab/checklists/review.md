# 画面レビュー観点

design-reviewer が UI のスクショを見るときの観点。上から重要な順。

## 1. 壊れていないか（要修正）

- 375px で横にはみ出している、要素が画面外に切れている
- 文字が重なっている、ボタン内で折り返して崩れている、省略されて意味が通らない
- 要素同士が重なっている、意図しない空白の帯がある
- 「テキスト」「XXX」「Lorem ipsum」などの仮文字が残っている
- コントラストが低く読めない（薄いグレーの小さい文字など）

## 2. 使えるか（要修正〜推奨）

- 画面の主目的（最も重要な情報・操作）が最初に目に入るか
- 主要な操作ボタンが 1 つに絞られ、目立っているか
- タップ対象が小さすぎないか（375px で 44px 四方が目安）
- 入力欄にラベルがあるか（プレースホルダーだけに頼っていないか）
- 状態（空・エラー・読み込み中）が必要な画面で考慮されているか

## 3. デザインシステムに沿っているか（推奨）

- 色・余白・角丸・文字サイズが tokens.css の段階に乗っているか（見た目で中途半端な値がないか）
- components.md の部品と見た目がそろっているか（ボタン・入力欄・カード・表）
- 文字サイズの段階が多すぎないか（1 画面に 4 段階まで）
- 余白のリズムが一定か（同じ関係の要素間は同じ間隔）

## 4. 細部（軽微）

- 数値の右寄せ・桁区切り・単位
- 左端・上端のそろい
- 文言の統一（ボタンは動詞で終える、です・ます／体言止め）
